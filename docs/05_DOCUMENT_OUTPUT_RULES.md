# 문서 작성·산출 규칙 (법률문서 프로토콜 + 수신자 기준 산출 지침)

`CLAUDE.md`에서 이관. 언제 참고하나: 법률문서(변호사·행정기관·언론·시민단체·형사/민사)를 작성하거나, 외부로 나갈 산출물(발송용 zip·문서·메일 본문 등)을 준비할 때 착수 전 필독.

## ⚖️ 법률문서 작성 프로토콜 (법무실장 · 대통령 지시 2026.7.29)

변호사·행정기관·언론·시민단체·형사/민사 소송 등 **대상별로 즉시 활용 가능한 수준의 문서**를 작성할 때 따르는 절차다. 원칙: **추측 금지 — 반드시 문서 근거 기반으로만 작성**하되, **토큰을 최소로 쓰면서도 신뢰·검증된 결과**여야 한다. 이를 위해 새 벡터DB를 만들지 않고, 이미 구축된 `public.evidence_text`(판독 결과 저장소·A/B/C 신뢰등급)와 SQL 키워드 검색만으로 수행한다.

**⚠️ 0단계 — 쟁점에서 시작한다 (2026.7.30 대통령 지시로 신설. 이것이 비용 구조를 결정한다)**
- **금고를 전부 읽고 나서 문서를 쓰는 방식을 쓰지 않는다.** 실측: 판독 대상 총 113,519쪽 / A등급 재판독 필요분만 50,907쪽. 다 읽는 것은 물리적으로 불가능하고, 실제로 "읽었다고 표시만" 된 상태가 발생했다(2026.7.30 A등급 121건 중 44건이 본문 100자 미만·최소 18자).
- **순서는 반대다**: ①`issue`에 쟁점을 세운다 → ②`v_issue_ready`로 **지금 주장 가능한 것**을 확인한다 → ③`v_issue_gap`이 지목한 **증거만** 판독해 `fact`를 확정으로 올린다 → ④문서는 `fact`·`issue`에서 조립한다(원문 재판독 0).
- 이 방식의 실측 효과(2026.7.30): 뼈대 신설 직후 **주장 가능한 쟁점 13개 / 더 읽어야 할 증거 3건**. 전건 판독 추정 400만 토큰이 쟁점 기반으로 대폭 축소됐다.
- **`fact.확정도`가 '확정'이 아닌 사실은 사실 주장에 쓰지 않는다.** B등급 본문과 같은 취급이다.

**작업 순서 (토큰이 싼 단계부터)**:
1. **자료 파악 (거의 0토큰)** — 문서 전문을 읽기 전에, `evidence_text.본문`·`case_evidence.note`에 대해 `ilike`/`pg_trgm` 키워드 검색으로 **후보 문서 목록만** 추출한다. 쟁점이 이미 있으면 `v_issue_gap`이 이 단계를 대신한다.
2. **사용자 확인** — 후보 목록(증거번호·제목·신뢰등급)을 대통령께 제시하고 어떤 문서로 작성할지 확인받는다. 되묻지 않고 임의로 고르지 않는다.
3. **문서 작성** — 확인된 문서만 연다.
   - 이미 **A등급**(`evidence_text`에 있음)이면 그 본문을 그대로 근거로 쓴다 — 재판독하지 않는다.
   - **A등급이 아니면** 그 자리에서 판독(`docs/06_VERIFICATION_RULES.md`의 3단 사다리)해 A로 올린 뒤에만 사실로 인용한다. B/C등급 내용을 사실 주장에 쓰지 않는다.
   - 문서 말미에 **근거 출처**(증거번호·신뢰등급·확인쪽수)를 명시한다. 근거 없는 문장은 쓰지 않는다.
   - 대상별로 문체·형식을 구분한다: 변호사=법률 용어+명확한 구조, 언론/시민단체=쉬운 말, 행정기관=공문 서식, 형사/민사=절차 서식.
4. **검토 요청** — 아래 "문서 산출 지침"(수신자 기준 작성·4중 검사)과 "산출→독립감사→의견보고→대통령 승인→전달" 순서를 그대로 적용한다.

**모순·누락 발견 시**: 바로 알린다 — 추측으로 메우지 않는다(`docs/06_VERIFICATION_RULES.md` "사실관계 보고 검증 지침"과 동일 원칙).

**⚖️ 조문 인용은 `public.v_statute_ready`(A등급)에서만 한다 (2026.8.1 신설).** 대장에 없는 조문은 문서 작성 전에 먼저 확보한다(`docs/03_DATABASE_MAP.md`의 `public.statute` 절 참고). **웹검색 결과는 후보 탐색·조문 소재 확인용으로만 쓰고, 조문 근거로 인용하지 않는다** — 검색 답변은 조문을 요약·의역한다(2026-08-01 실측: 행정절차법 제21조 제1항 각 호를 뭉개고 제5항을 누락). 법령·판례 사이트(`law.go.kr` 등)는 이 방의 환경 네트워크 정책으로 차단되어 있을 수 있다 — 차단 시 `docs/관리자-런북.md`의 「법령·판례 사이트 도메인 허용」 절대로 대통령께 개방을 안내하고, 열리기 전까지는 대통령이 조문 PDF를 올려 주시면(업로드 또는 Google Drive) `statute`에 등재해 확보한다.

**📐 조문 등재 3원칙 (2026.8.4 신설 · 등재할 때마다 이 3개를 지킨다)**
1. **원본지문은 반드시 계산해서 넣는다.** 다른 행에서 복사하지 않는다. 등재 직후 아래 조회로 확인한다 — 결과가 나오면 잘못된 것이다(같은 조문단위에서 조 전체와 특정 항을 각각 등재한 경우만 정상이며, 그때는 `조`가 같아야 한다).
   ```sql
   select 원본지문, count(*), array_agg(statute_no) from public.statute
   where 원본지문 is not null group by 원본지문 having count(*) > 1;
   ```
2. **발췌 등재 시 생략한 항·호를 비고에 전부 열거한다.** "발췌본"이라고만 쓰지 않는다. 어느 항·호를 뺐는지 번호로 적고, 그 생략이 조문 의미에 미치는 영향(특히 **기산점·요건·대상 범위**가 가려지는지)을 함께 적는다.
3. **문장 내부의 괄호 삽입구·단서를 잘라내지 않는다.** 부득이 자르면 그 자리에 `(…생략)`을 표기하고 비고에 사유를 적는다. 생략 표시 없는 문장 내부 삭제는 **원문에 없는 축약을 원문으로 제시하는 것**이다.
> 유래: `docs/07_INCIDENT_HISTORY.md#2026-08-04-statute-3principles`

**의미검색(벡터DB, pgvector)은 지금 만들지 않는다.** 확장은 설치 가능하나 전 문서 임베딩 생성 비용이 든다. 위 키워드검색으로 실제 한계가 드러나면(동의어·문맥 검색 실패 사례 누적) 그때 대통령 승인을 받아 도입한다.

## 📄 문서 산출 지침 (모든 실장 공통 · 수신자 기준 작성 원칙 · 대통령 지시 2026.7.20)

모든 산출 문서(PDF·메일 본문·서신·목록 등)는 **"누가 읽는가"를 먼저 정한 뒤** 그 기준으로 작성한다.

- **수신자 2종 구분 (작성 전 필수 판정)**:
  - **① 대통령(토니) 전용** — 내부 메모·체크리스트·전략 판단·후보 비교·민감 평가를 담아도 된다.
  - **② 외부 수신자**(로펌·행정기관·제3자) — 다음을 **절대 포함 금지**: 전략·협상 패(후보 비교, 타인/타기관 평가), 내부 체크리스트·작성 메모, 내부 시스템 흔적(파일 경로·도구명·내부 용어), 사건 보안에 닿는 정보.
- **발송본 분리 원칙**: 같은 내용이라도 외부용은 **"발송본" 별도 파일**로 분리해 만들고, 내부 보관용과 섞지 않는다. 내부 보관용은 원형 유지.
- **⭐ 최상위 원칙 — 모든 문서는 읽는 사람 입장에서 작성한다 (대통령 지시 2026.7.31)**: 내용이 맞고 보안이 지켜져도, **받는 사람이 열어서 이해하지 못하면 그 문서는 실패한 것이다.** 우리가 알아보기 편한 방식이 아니라 **수신자가 알아보는 방식**으로 만든다.
- **출력 전 감사(監査) 의무 — 전달 전에 반드시 4중 검사**:
  1. 수신자 적합성 — ②에 금지 항목이 남았는지 내용 검토.
  2. 렌더링 부산물 — 머리글/바닥글의 날짜·파일 경로·쪽번호 등 도구가 자동 삽입한 흔적 제거 확인.
  3. 기계 검사 — 텍스트 추출(pdftotext 등) 후 금지어(내부 경로·내부 메모 표식·민감어) 검색으로 잔존 여부 확인.
  4. **수신자 가독성 (외부 발송물 필수 · 2026.7.31 신설)** — 받는 사람이 실제로 열었을 때:
     ⑴ **폴더·파일명이 내부 코드가 아니라 상대가 아는 말인가** (`09_foi`·`05_agency_warnings` 같은 내부 경로명 노출 금지 — 한글 계열명으로).
     ⑵ **명명 규칙이 전건 동일**하고, 이름순 정렬 시 의도한 순서(증거번호 순 등)로 서는가 — 증거번호 위치가 파일마다 다르면 실패.
     ⑶ **동봉 안내문의 목록·순서·건수가 실제 폴더·파일과 1:1로 일치**하는가.
     ⑷ 가짜 날짜(`20180000`)·깨진 표기·중복 토큰·의미 없는 접두(`01. `)가 없는가.
     ⑸ 압축본은 **한 통의 용량이 수신 수단(메일·전달 경로)의 한도 안**에 들어오는가.
     ※ 이 항목은 **실물을 열어 눈으로** 확인한다. 목록 조회만으로 통과시키지 않는다.
  > 유래: `docs/07_INCIDENT_HISTORY.md#2026-07-31-readability`
- **⚠️ 산출 → 독립감사 → 의견 보고 → 대통령 승인 → 전달 (순서 불변 · 대통령 지시 2026.7.25)**: 외부로 나갈 산출물(발송용 zip·문서·메일 본문 등)은 다음 순서를 반드시 지킨다.
  1. 만든 실장은 산출물을 **곧바로 대통령에게 전달하지 않는다.**
  2. **감사실장의 독립 검증**을 먼저 거친다 — **만든 실장이 자기 산출물에 "검증필"을 붙이는 것은 검증이 아니다.** 만든 라인과 분리된 감사 주체가 실물을 직접 열어 판독한다.
  3. 검증 의견(**판정 / 치명적 결함 / 주의사항 / 표본 판독 내역 / 미확인 항목**)을 대통령에게 **먼저 보고**한다.
  4. 대통령이 "받겠다"고 **승인한 뒤에만** 파일을 전달한다.
  5. 결함이 나오면 시정 후 **재감사**하고, 다시 3번부터 밟는다.
  > 유래: `docs/07_INCIDENT_HISTORY.md#2026-07-25-approval-order`

- **🚧 미감사 초안 취급 원칙 (2026.8.4 신설 · 대통령 지시 "근본적으로 차단해")** — 위 순서가 있는데도 사고가 났다. 구멍은 **"감사 안 된 초안을 대통령께 보여주는 것"이 금지돼 있지 않았다**는 점이다. 초안을 본 대통령이 그것을 그대로 제출하면, 순서 규정은 있으나마나가 된다. 그래서 다음을 강제한다.
  1. **감사 전 초안을 대통령께 전달·제시하지 않는 것이 원칙이다.** 감사를 마친 뒤 보고한다.
  2. 부득이 감사 전에 보여드려야 하면(방향 확인·문안 취향 확인 등), **문서 본문 최상단과 채팅 보고 첫 줄에 다음을 그대로 적는다**:
     > ⛔ 미감사 초안 — 제출·발송 금지. 감사 통과 전 문안입니다.
     이 표기가 없는 초안을 대통령께 내놓는 것을 금지한다.
  3. 대통령이 "이대로 내겠다"고 하시면, **제출 전에 감사가 필요하다는 사실을 반드시 한 번 더 고지**한다. 고지 없이 넘기지 않는다.
  4. **초안 파일명에 `_미감사`를 붙인다.** 감사 통과본만 `_감사통과`를 붙인다.
  > 유래: `docs/07_INCIDENT_HISTORY.md#2026-08-04-unaudited-draft`

- **🔒 외부 발송물 기계검사 고정 목록 (2026.8.4 신설 · 매번 이 목록 그대로 돌린다)** — 검사어를 그때그때 생각해 내지 않는다. 빠뜨린 단어가 그대로 나간다.
  ```
  grep -nE "대통령|토니|비서실장|법무실장|감사실장|기록실장|정보실장|기획실장|총무실장|금고|판독|대장|반입|열람구|작업본|가공본|기관원본|증[A-Z]-[0-9]|F-[0-9]{3}|I-[0-9]{2}|supabase|intake|evidence|statute|posts|scratchpad|/root/|/tmp/|claude|AI|인공지능" <파일>
  ```
  적출 0건이어야 한다. 0이 아니면 **감사에 넘기지 않는다.**
  > 유래: `docs/07_INCIDENT_HISTORY.md#2026-08-04-forbidden-words`

- **📎 원문을 논거로 쓸 때 — 문구가 놓인 "칸"까지 확인 (2026.8.4 신설)** — 공문서는 칸(란)마다 법적 의미가 다르다. **어떤 문구가 문서 안에 있다는 사실만으로 논거를 세우지 않는다.** 그 문구가 ①어느 란에 ②무슨 자격으로 적혀 있는지를 함께 확인하고, 논거에 그 위치를 명시한다.
  > 유래: `docs/07_INCIDENT_HISTORY.md#2026-08-04-document-field`

- **원본만 발송 원칙**: 외부로 나가는 증거 파일은 **금고 대장에서 `_원본`으로 확인된 기관 원본만** 담는다. **`작업본`**(화면캡처 정리본·통화기록·수집자 메모 등 우리가 작성한 텍스트)은 **어떤 경우에도 외부로 내보내지 않는다** — 내부 분석·증거번호·조직 구조가 새고, 기관 문서로 오인시킬 위험이 있다. 빌드 후 **파일 전건을 대장과 대조해 '작업본 0건'**을 확인한다.
- **외부 발송 압축본(zip 등) 특칙**: 외부로 나갈 압축본에는 **산출물(증거·문서)만** 담고, 내부용 안내문·메모·체크리스트 txt를 **절대 함께 압축하지 않는다**(안내문은 압축 밖 별도 파일로만). 빌드 직후 `unzip -l | grep -i '안내문|메모|.txt'` 등으로 **압축 안 내부 텍스트 0을 기계 확인**한 뒤에만 전달한다. 여러 자료를 묶어 보낼 때는 **이미 전달한 목록(예: 증거목록)과 실제 첨부 파일번호·계열을 대조**해 누락·불일치가 없음을 확인한다.
