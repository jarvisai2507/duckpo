## 🎫 토큰 관리 규칙 (모든 실장 공통 · 대통령 지시 2026.7.29)

대통령 지시: **"토큰을 최소로 쓰면서 신뢰 있는 결과를 내라. 중요한 작업을 할 때는 사용량을 보여라. 토큰이 없어서 일을 못 하는 상황이 없어야 한다 — 일을 계속 이어나가야 하기 때문이다."**

- **중요 작업(2·3등급) 착수 시 예상 사용량, 종료 시 실사용량을 보고한다.** 대통령이 남은 여력을 알고 판단할 수 있어야 한다.
- **⏱️ 진행 중 실시간 표시 (2026.8.2 신설 · 대통령 지시)**: 착수·종료만으로는 부족하다. **긴 작업은 진행 도중에도 사용량이 보여야 한다.**
  - **① 서브에이전트 단위 즉시 보고(기본)**: 서브에이전트가 하나 끝날 때마다 그 회신에 실린 토큰 수를 **그 자리에서 대통령께 숫자로 알린다**. 여러 개를 돌렸으면 마지막에 합계를 낸다. 끝나고 몰아서 보고하지 않는다.
  - **② `Workflow` 도구 사용(3개 이상 병렬·장시간 작업)**: 스크립트 안에서 `budget.spent()`로 누적 토큰을 읽어 `log()`로 찍으면 **작업 도중에 실시간으로 표시된다**. 건당 완료 시점마다 `log(\`… 누적 ${Math.round(budget.spent()/1000)}k 토큰\`)` 형태로 남긴다. (대통령은 `/workflows`로 진행 상황을 직접 볼 수도 있다.)
  - ⚠️ **Workflow 스키마 항목명은 반드시 영문**(`^[a-zA-Z0-9_.-]{1,64}$`)으로 쓴다. 한글 키를 쓰면 API 400으로 **전 건이 시작도 못 하고 실패**한다(2026.8.2 실측 — 3건 전부 실패, 재작성으로 복구).
  - **③ 대통령이 승인해야 켜진다**: `Workflow`는 다수 에이전트를 띄워 토큰을 크게 쓰므로, 대통령이 명시적으로 쓰라고 한 경우에만 쓴다.
  > 유래: 2026.8.2 대통령이 "토큰 사용량을 실시간으로 보여주기로 하지 않았느냐"고 묻자 규칙서를 확인한 결과 **착수·종료 보고만 있고 진행 중 표시 규칙이 아예 없었다.** 그날 서브에이전트 5개(합계 522,113토큰)의 사용량이 회신마다 도착해 있었는데도 대통령께 한 번도 보고되지 않은 사실이 함께 드러났다 — 규칙이 없으니 데이터가 있어도 흘렀다.
- **🖥️ 대통령 평시 모델 설정 (2026.8.2 신설)**: 화면 우측 하단 모델 선택은 **"Sonnet 5" · 노력수준 "중간"**을 기본으로 둔다. opus로 직접 바꿀 필요 없음 — 2등급 판독이 필요한 순간은 비서실장이 알아서 판단해 강제 체크리스트 0항대로 처리한다(세션이 sonnet이면 opus 서브에이전트에 위임, opus로 직접 바꾸신 경우엔 비서실장이 그 자리에서 직접 판독). **주간 전체 모델 한도가 80%를 넘어선 기간에는** 노력수준을 "더 빠르게" 쪽으로 낮춰 재설정 시점까지 버티는 것을 권장한다(한도 재설정 후 "중간"으로 복귀).
- **🚦 주간 한도 신호등 (2026.8.2 신설)** — 무거운 작업(2·3등급, 특히 서브에이전트·`Workflow` 신규 실행) 착수 전 대통령의 사용량 화면(주간·전체 모델 %)을 확인한다.
  - 🟢 잔여 50%↑ — 그대로 진행.
  - 🟡 잔여 20~50% — 예상 토큰과 함께 진행 여부를 여쭙는다.
  - 🔴 **잔여 20% 미만(=80% 이상 소진)** — **새 서브에이전트·`Workflow` 착수를 자동 금지**하고, 남은 기한 중 지금 당장 필요한 일이 있는지부터 확인한 뒤 대통령께 보고·승인 후에만 예외적으로 진행한다. 조절 수단: ①표본만 검증(전건→기한 임박분만) ②이중 검증 생략(위임 또는 직접 중 하나만) ③미루기(재설정 이후로) ④싼 방법 대체(재판독 대신 기존 A등급 인용).
  - **서브에이전트 고정비를 기억한다**: 호출 1회당 실측 약 10만 토큰(내용 난이도 무관, 강제 체크리스트 0항 참고) — "가벼운 확인이니 서브에이전트 하나만 더 띄우자"는 판단 자체가 이미 10만 토큰 판단이다.
  - 유래: 2026.8.2 "판독은 무조건 opus 서브에이전트 위임" 규칙을 신설한 지 한 시간 만에 그 방식이 원인이 되어 **주간 전체 모델 한도가 88%까지 소진**됐다(사용량 화면의 "한도를 사용하고 있는 항목" 1위가 general-purpose 서브에이전트 32%). 이미 돌아가던 재검증 작업(opus 서브에이전트 3건, 예상 30만 토큰)을 대통령이 화면을 보여준 즉시 중단했고, 확인 결과 재설정 시점(화요일)까지 놓치는 기한이 없어 실손실은 없었다.
- **대화가 300k를 넘으면 그 시점에 인계 준비를 시작한다** — 계획서 갱신 + 금고 기록 저장. 한계에 부딪혀 맥락이 잘리는 것보다 미리 넘기는 것이 싸다.
- **판독은 싼 단계부터**: 텍스트 추출 → 필요한 것만 렌더링. 단 "못 읽었다"고 쓰기 전에는 반드시 렌더링(강제 체크리스트 1·8).
- **감사·대량 판독은 서브에이전트로 돌린다** — 별도 맥락이라 본 대화를 소모하지 않는다.
- **같은 문서를 두 번 읽지 않는다** — `evidence_text`(A등급)에 있으면 그대로 인용한다.
- **되묻기 전 금고를 먼저 뒤진다** — 물어보는 것이 싸 보이지만, 이미 금고에 있는 답을 물으면 대통령의 시간과 신뢰를 쓴다(강제 체크리스트 4).
