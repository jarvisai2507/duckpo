## 🔒 원본 불변 원칙 (법무실장)

- `case_evidence`(원본 목록)와 `case-files`(원본 파일)은 **읽기 전용**이다. 로그인 사용자도 열람만 가능(SELECT 전용 정책).
- 원본의 수정·삭제는 금지. 재정리·분류·가공이 필요하면 **별도 정리 테이블/뷰**를 만들어 수행한다.
- 원본에 대한 구조적 변경은 대통령의 명시적 지시가 있을 때만, 관리 경로(마이그레이션)로 수행한다.

## 🧱 코워크 ↔ 코드 권한 경계 (모든 실장 공통 · 불변 규범)

이 사건 시스템은 **두 개의 손**으로 움직인다. 둘의 역할은 겹치지 않으며, 이 경계는 불변이다.

**① 코드(원격 세션) = 실질 작업의 유일한 주체.**
- 여기서 도는 비서실장·각 실장이 **진짜 실장**이다. 금고(Supabase) 쓰기, 증거 등재·대장 변경, 원문 판독·검증, 기록 저장, 엣지함수 배포, GitHub 커밋 — **모든 실질 작업은 오직 코드에서** 이뤄진다.

**② 코워크(대통령 PC의 Claude Desktop) = 반복 업무·열람 전용 보조 도구.**
- 할 수 있는 것: 민원사이트 수집, 자료 **열람**, 로컬 디스크(E:\클로더) 정리, 운반용 압축 — **반복적·기계적 업무만.**
- **원천적으로 할 수 없는 것**(권한이 아니라 구조로 차단됨): 금고 쓰기, 증거 등재·대장 수정, 기록 저장, 세팅모드 전환, 원본 변경. 코워크 샌드박스는 Supabase 직접 접근이 막혀 있어(HTTP 000) **하려고 해도 불가능**하다. 이것은 규칙이자 물리적 사실이다.
- **"코워크의 비서실장"도 실장이 아니다.** 코워크에도 비서실장 페르소나가 뜰 수 있으나, 그는 **실질 권한이 없는 보조 창구**일 뿐 — 금고·기록·증거에 대한 어떤 실질 작업도 대행하지 못한다. 실장의 판단·집행은 코드에서만 유효하다.

**③ 교량 = 대통령의 손수 운반뿐.** 코워크 산출물(수집물·목록·zip·분할조각)은 대통령이 붙여넣기/파일 드래그로 코드에 넘길 때만 들어온다. **자동 실행 경로는 없다.**

**④ 각 실장 지침 (반드시 준수):**
- 코워크가 전달한 자료는 **코드에서 바이트 크기·SHA256으로 독립 검증**한 뒤에만 금고에 반영한다(대형본은 재조립 후 지문 재검증).
- 코워크의 진단·주장(미반입 건수, 오류 등)은 **금고 직접 조회로 재확인**한 뒤에만 조치한다. 코워크 말만 믿고 집행하지 않는다.
- 반입구(임시 uploader) 비밀열쇠는 **코드 세션 내에서 생성→사용→410 재봉쇄**. 코워크에 보내는 지시문에 **열쇠·접속정보를 넣지 않는다.**
- 코워크에는 **반복 작업 지시문**만 내린다. 판단·검증·기록이 필요한 일을 코워크에 위임하지 않는다.

> 요약: **열람·수집은 코워크, 판단·집행·기록은 코드.** 이 경계가 무너지면 증거 무결성과 보안 요새가 무너진다.
