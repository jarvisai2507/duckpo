# 실무 절차 (기록 저장 SQL · 토큰 관리 · 정기 구조 공시)

`CLAUDE.md`에서 이관. 언제 참고하나: `posts` 기록을 실제로 저장할 때(SQL 템플릿), 토큰 사용량을 관리할 때, 정기 구조 공시를 할 때.

## 대화 기록 저장 SQL 절차

> 발동어·발동 시점·완전성 원칙·category 확인 절차는 `CLAUDE.md`의 "⭐ 대화 기록 규칙"에 있다. 여기는 실제 SQL 실행 절차.

1. **요약 + 상세 작성**: 현재 세션에서 나눈 대화 전체를 한국어로 정리하되 **두 층으로 구분**한다.
   - `title`: 대화의 핵심을 담은 짧은 제목 (한 줄)
   - `summary`: **요약** — 몇 줄로 핵심만. 나중에 목록을 훑을 때 무슨 일이었는지 바로 알 수 있게.
   - `detail`: **상세내용** — 시간이 지나 잊어도 복기할 수 있도록 구체적으로: 경위, 내린 결정과 이유, 수행한 조치/명령, 바뀐 상태, 남은 일.
2. **게시판 분류(`category`) 확인**: INSERT 전, 어느 게시판(변호사/언론/시민단체/형사/민사/미분류) 소관인지 먼저 여쭙는다.
3. **Supabase `public.posts`에 INSERT** (Supabase MCP `execute_sql`, project `rspxgsytxhlsauqohdbe`):
   - 날짜/시간은 **한국 시간(KST)**: `TZ=Asia/Seoul date '+%Y-%m-%d %H:%M'`
   - `NNN` 채번(같은 날짜 안에서 001부터 증가) — 먼저 조회:
     ```sql
     select coalesce(max(substring(id from 12)::int), 0) + 1 as next_n
     from public.posts where date = 'YYYY-MM-DD';
     ```
   - INSERT (summary/detail은 dollar-quoting `$q$...$q$` / `$d$...$d$` 사용 권장 — 따옴표/줄바꿈 안전):
     ```sql
     insert into public.posts (id, date, time, title, summary, detail, tags, dept, category)
     values ('YYYY-MM-DD-NNN', 'YYYY-MM-DD', 'HH:MM', '제목', $q$요약$q$, $d$상세내용$d$, array['태그'], '실장key', '분류값또는NULL');
     ```
   - `tags`는 대화 주제에 맞게 1~3개 (예: "개발", "일상", "업무")
   - `dept`는 대화 주제를 담당하는 **실장 key** (예: 웹 정보 취합이면 "정보실장", 법률이면 "법무실장"). 판단이 어려우면 "기록실장". 조직도(`org.html`)가 이 값으로 실장별 기록 건수를 센다.
   - `category`는 위 2단계에서 확인받은 값(변호사/언론/시민단체/형사/민사) 또는 `null`.
   - INSERT 후 확인: `select id, title from public.posts where id = '<새 id>';`
4. **commit & push는 기록에는 불필요** — 기록은 Supabase에만 저장되며 사이트에 즉시 반영된다. commit & push는 **코드(html/js/워크플로/CLAUDE.md 등) 변경이 있을 때만** 수행한다.
5. **다이어그램/알림**: 기록이 저장되었음을 알리고 페이지 주소(https://jarvisai2507.github.io/duckpo/ · 로그인 필요)를 전한다.

주의: 기존 기록 행을 UPDATE/DELETE 하지 말 것 (사용자가 명시적으로 요청한 경우 제외). 실장(`org.html`의 key) 이름을 바꾸거나 추가할 때는 `org.html`의 `LINE`/상수와 `dept` 값이 일치하도록 유지한다.

## 🎫 토큰 관리 규칙 상세 (모든 실장 공통 · 대통령 지시 2026.7.29)

> 핵심 한 줄(주간 한도 20% 미만이면 신규 서브에이전트/Workflow 자동 금지)은 `CLAUDE.md`에 있다. 여기는 실무 상세.

대통령 지시: **"토큰을 최소로 쓰면서 신뢰 있는 결과를 내라. 중요한 작업을 할 때는 사용량을 보여라. 토큰이 없어서 일을 못 하는 상황이 없어야 한다 — 일을 계속 이어나가야 하기 때문이다."**

- **중요 작업(2·3등급) 착수 시 예상 사용량, 종료 시 실사용량을 보고한다.** 대통령이 남은 여력을 알고 판단할 수 있어야 한다.
- **⏱️ 진행 중 실시간 표시 (2026.8.2 신설 · 대통령 지시)**: 착수·종료만으로는 부족하다. **긴 작업은 진행 도중에도 사용량이 보여야 한다.**
  - **① 서브에이전트 단위 즉시 보고(기본)**: 서브에이전트가 하나 끝날 때마다 그 회신에 실린 토큰 수를 **그 자리에서 대통령께 숫자로 알린다**. 여러 개를 돌렸으면 마지막에 합계를 낸다. 끝나고 몰아서 보고하지 않는다.
  - **② `Workflow` 도구 사용(3개 이상 병렬·장시간 작업)**: 스크립트 안에서 `budget.spent()`로 누적 토큰을 읽어 `log()`로 찍으면 **작업 도중에 실시간으로 표시된다**. 건당 완료 시점마다 `log(\`… 누적 ${Math.round(budget.spent()/1000)}k 토큰\`)` 형태로 남긴다. (대통령은 `/workflows`로 진행 상황을 직접 볼 수도 있다.)
  - ⚠️ **Workflow 스키마 항목명은 반드시 영문**(`^[a-zA-Z0-9_.-]{1,64}$`)으로 쓴다. 한글 키를 쓰면 API 400으로 **전 건이 시작도 못 하고 실패**한다.
  - **③ 대통령이 승인해야 켜진다**: `Workflow`는 다수 에이전트를 띄워 토큰을 크게 쓰므로, 대통령이 명시적으로 쓰라고 한 경우에만 쓴다.
  > 유래: `docs/07_INCIDENT_HISTORY.md#2026-08-02-token-realtime`
- **🖥️ 대통령 평시 모델 설정 (2026.8.2 신설)**: 화면 우측 하단 모델 선택은 **"Sonnet 5" · 노력수준 "중간"**을 기본으로 둔다. opus로 직접 바꿀 필요 없음 — 2등급 판독이 필요한 순간은 비서실장이 알아서 판단해 `docs/06_VERIFICATION_RULES.md` 강제 체크리스트 0항대로 처리한다. **주간 전체 모델 한도가 80%를 넘어선 기간에는** 노력수준을 "더 빠르게" 쪽으로 낮춰 재설정 시점까지 버티는 것을 권장한다(한도 재설정 후 "중간"으로 복귀).
- **🚦 주간 한도 신호등 (2026.8.2 신설)** — 무거운 작업(2·3등급, 특히 서브에이전트·`Workflow` 신규 실행) 착수 전 대통령의 사용량 화면(주간·전체 모델 %)을 확인한다.
  - 🟢 잔여 50%↑ — 그대로 진행.
  - 🟡 잔여 20~50% — 예상 토큰과 함께 진행 여부를 여쭙는다.
  - 🔴 **잔여 20% 미만(=80% 이상 소진)** — **새 서브에이전트·`Workflow` 착수를 자동 금지**하고, 남은 기한 중 지금 당장 필요한 일이 있는지부터 확인한 뒤 대통령께 보고·승인 후에만 예외적으로 진행한다. 조절 수단: ①표본만 검증(전건→기한 임박분만) ②이중 검증 생략(위임 또는 직접 중 하나만) ③미루기(재설정 이후로) ④싼 방법 대체(재판독 대신 기존 A등급 인용).
  - **서브에이전트 고정비를 기억한다**: 호출 1회당 실측 약 10만 토큰(내용 난이도 무관) — "가벼운 확인이니 서브에이전트 하나만 더 띄우자"는 판단 자체가 이미 10만 토큰 판단이다.
  > 유래: `docs/07_INCIDENT_HISTORY.md#2026-08-02-weekly-limit`
- **대화가 300k를 넘으면 그 시점에 인계 준비를 시작한다** — 계획서 갱신 + 금고 기록 저장. 한계에 부딪혀 맥락이 잘리는 것보다 미리 넘기는 것이 싸다.
- **판독은 싼 단계부터**: 텍스트 추출 → 필요한 것만 렌더링. 단 "못 읽었다"고 쓰기 전에는 반드시 렌더링(`docs/06_VERIFICATION_RULES.md` 강제 체크리스트 1·8).
- **감사·대량 판독은 서브에이전트로 돌린다** — 별도 맥락이라 본 대화를 소모하지 않는다.
- **같은 문서를 두 번 읽지 않는다** — `evidence_text`(A등급)에 있으면 그대로 인용한다.
- **되묻기 전 금고를 먼저 뒤진다** — 물어보는 것이 싸 보이지만, 이미 금고에 있는 답을 물으면 대통령의 시간과 신뢰를 쓴다.

## 📐 정기 구조 공시 (총무실장 · 정기)

- 금고 데이터 구조도(테이블·버킷·계열 분포·보안 구도)를 **주기적으로 갱신해 게시판에 공시**한다(다이어그램 아티팩트 + `posts` 기록).
- 시점: 증거 계열/테이블 구조에 **중대한 변경**이 있을 때, 또는 **정기(권장 주 1회)**. 큰 변화가 없으면 "변동 없음"으로 간단히 갱신.
- 공시 기록은 `dept='총무실장'`, `tags`에 `'구조공시'` 포함. 다이어그램 URL과 그 시점 핵심 수치(대장·금고·계열 수)를 요약에 남긴다.
