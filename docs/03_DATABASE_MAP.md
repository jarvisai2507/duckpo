# DB 테이블·뷰 지도 (Supabase 인프라 상세)

`CLAUDE.md`의 "Supabase 인프라" 절 전문 이관. 언제 참고하나: 새 테이블·뷰를 만들거나, 기존 테이블·뷰의 정확한 용도·컬럼·검증 규칙을 확인해야 할 때.

- 프로젝트: `rspxgsytxhlsauqohdbe` (https://rspxgsytxhlsauqohdbe.supabase.co)

## 핵심 테이블

- `public.posts` — 일일 기록. (id text PK "YYYY-MM-DD-NNN", date, time, title, summary(요약), detail(상세내용), tags text[], dept, category, created_at). RLS: authenticated 전용, anon 차단.
  - `category` — **대상별 게시판 분류**(변호사/언론/시민단체/형사/민사, null=미분류). `dept`(실장 조직 축)와는 **다른 축**이니 혼동하지 않는다. 체크 제약으로 허용값이 고정되어 있어, 새 분류를 추가할 때는 마이그레이션으로 제약을 갱신해야 한다(대통령 명시적 지시 필요 — 금고 구조 변경 원칙과 동일).
- `public.case_evidence` + 버킷 `case-files` — **사건 자료 대장(법무실장 소관, 296건)**. 비공개 버킷. **"원본 모음"이 아니라 원본과 작업본이 함께 든 자료고**이므로, 외부로 낼 때는 반드시 성격을 가려낸다.
- `public.evidence_class` — **자료 성격 딱지 대장**. `case_evidence`(원본 불변)를 손대지 않고 건별 `성격`(기관원본/제3자원본/가공본/작업본/미확정)·`발송가부`·`판정근거`만 별도 적재한다. 판정은 원문 판독을 근거로 하며, 근거를 `판정근거`에 남긴다.
- `public.v_sendable` — **외부 발송 허용 목록 뷰**. 발송본 빌드는 **반드시 이 뷰에서만** 뽑는다. 작업본·미확정은 구조적으로 배제된다.
- `public.v_unclassified` — 딱지가 아직 안 붙은 자료. 여기 남아 있는 건은 발송 대상이 될 수 없다. **평시 0건을 유지**한다.
- `public.category_meta` — **게시판 탭 표시 설정**(2026.7.29 신설. `category`·`label`·`emoji`·`color`·`color_soft`·`sort_order`). 탭 이름·색·순서를 바꾸고 싶다는 요청이 오면 **이 표를 UPDATE**한다 — `index.html`은 접속 시마다 이 표를 읽어 그리므로 **코드 수정·배포 없이 즉시 반영**된다. 단, 완전히 새로운 분류값 추가/삭제는 `posts_category_check` 제약을 바꿔야 하므로 별도 마이그레이션(대통령 명시적 지시 필요)이다 — 이름·색만 바꾸는 것과는 다르다.

## 판독·사실 뼈대

- `public.evidence_text` — **판독 결과 저장소**(2026.7.28 신설). `case_evidence`(원본 불변) 원문을 판독한 텍스트를 담아, 같은 문서를 매번 다시 읽지 않게 한다. `신뢰등급`(A/B/C)은 사람이 값을 넣을 수 없는 GENERATED 칼럼이다. `v_text_ready`(A등급만)·`v_text_todo`(미판독·C등급) 뷰 참고. 상세 규칙은 `docs/05_DOCUMENT_OUTPUT_RULES.md`("법률문서 작성 프로토콜") 참고.
  - **A등급 조건(2026.7.30 강화)**: `판독방법 ∈ {이미지육안, 혼합}` AND `총쪽수 ≤ 2000` AND `확인쪽수 ≥ 총쪽수` AND **쪽당 30자 이상 본문**. B등급도 쪽당 30자 하한이 같다(판독방법만 글자추출).
  - 유래: `docs/07_INCIDENT_HISTORY.md#2026-07-30-evidence-text-a-grade`
- **`public.fact` 사실대장 + `public.issue` 쟁점대장 — 뼈대(3층)**(2026.7.30 신설. 대통령 지시: *"모든 내용을 다 읽고 뼈대를 세운 후 행정·민사·형사·언론·시민단체·국토부 국정보고용으로 대응하려면 전략을 세워야 하는 것 아니냐. 매번 검수하고 열어보면 시간·토큰을 어떻게 감당하느냐."*)
  - **왜 만들었나**: 원문(1층)·판독(2층)만 있어 문서를 쓸 때마다 원문을 다시 열었다. 대상이 6개면 같은 서류를 6번 읽는다. **한 번 읽고 여섯 번 쓰는** 구조로 바꾼 것이다.
  - `fact` — 사실 하나를 한 번만 확정하고 근거를 붙인다. `확정도`=확정이면 `인용문`·`확인쪽수`·`근거증거`가 반드시 있어야 한다(CHECK). **근거 없는 "확정"을 DB가 거부한다.**
  - `issue` — 논거를 "어떤 사실들의 조합"으로 정의한다. `상태`=붕괴면 **그 논거를 쓰는 모든 문서가 조회 한 번으로 드러난다**.
  - **`v_issue_ready`** — 필요사실이 전부 확정인 쟁점 = **지금 주장할 수 있는 것.**
  - **`v_issue_gap`** — 미확정 사실이 있는 쟁점 + 읽어야 할 증거 목록. ★**이것이 판독 대기열이다.** 금고 전체(5만 쪽)를 읽는 것이 아니라 **여기 뜬 것만** 읽는다.
  - **`v_fact_orphan`** — 어느 쟁점에도 안 쓰이는 사실(과잉 판독 감지).
  - **대상별 문서(행정·민사·형사·언론·시민단체·국정보고·변호사)는 이 두 표에서 조립한다 — 원문 재판독 0회.** 대상별로 달라지는 것은 문체·형식·강조점뿐이다.
  - ⚠️ **배열 CHECK 함정**: `array_length(빈 배열, 1)`은 0이 아니라 **NULL**이고, NULL 비교는 CHECK를 통과한다. 배열 최소 길이를 강제할 때는 반드시 `coalesce(array_length(x,1),0) >= 1`로 쓴다.
  - 유래: `docs/07_INCIDENT_HISTORY.md#2026-07-30-array-check-trap`
- **`public.statute` 법령 대장**(2026.8.1 신설. 배경: 법령·판례 사이트가 환경 네트워크 정책으로 전면 차단돼 조문을 축자 확인하지 못한 채 문서를 쓴 사고). `fact`와 동일한 규약 — `상태`(필요/확보)가 '확보'면 `축자본문`(30자 이상)·`시행일`·`출처`가 반드시 있어야 한다(CHECK). `신뢰등급`(A/B/C)은 GENERATED — `확보방법`이 `웹검색`이면 구조적으로 항상 C가 되어 인용 경로에서 배제된다. **`v_statute_ready`**(A등급) — 법률문서가 조문을 인용할 수 있는 유일한 출처. **`v_statute_todo`** — 대통령이 받아오셔야 할 조문 목록.
- **논리 뼈대 상위계층 — 처분대장·시간축·사실상충 (2026.8.5 신설. 배경: "논리의 핵심축이 튼튼해야 방지책이 의미 있다"는 대통령 지시로 5관점 적대적 재검증을 돌린 결과, 이 사건을 실제로 죽일 수 있는 두 축이 빠져 있었음이 드러남)**
  - **`public.disposition`(처분대장)** — 행정소송의 기본 단위. 2026-310호(연장승인, 유일하게 제소기간 살아있음)·2024-211호·2010-120호 등 처분별 상태(유효/취소/실효/대체)를 관리. `issue.대상처분_no`로 쟁점과 연결 — 처분이 취소·대체되면 그에 걸린 쟁점의 생사를 계산할 수 있게 한다.
  - **`public.deadline_critical`(불가역 기한 전용 대장)** — 처분별 제소기간·죄명별 공소시효 등. `fact.일자`만으로는 만료일 계산이 안 되어 신설. **`법적확정여부`가 '변호사확인완료'가 아니면 대외 문서에 특정 죄명·기산점을 단정 인용하지 않는다.** `v_deadline_critical_watch`(잔여일 포함, 생존 건만)로 D-day 확인.
  - **`public.fact_conflict`(사실 간 상충 표시)** — 같은 사실이 서로 다른 쟁점에서 반대로 작동하는 경우(예: F-035가 I-13 보강용인데 I-16을 정면 부정)를 표시. `issue_relation`(쟁점간 관계)은 쟁점↔쟁점만 보므로 사실 단위 상충은 못 잡는다.
  - **`public.v_axis_board`** — 위 3가지의 위험신호(기한도과·미연결사실·미해소상충)를 합산한 단일 상황판. **`v_intake_status`(강제 브리핑 첫 줄)에 3종 편입 완료.**
  - 유래: `docs/07_INCIDENT_HISTORY.md#2026-08-05-axis-board`

## 인증·설정

- 가입 차단: `auth.users` BEFORE INSERT 트리거(`block_signups_when_user_exists`) — **대통령(president) 1명 + 관리자(admin) 1명**만 허용(역할은 `raw_user_meta_data.role`), 그 외 가입 전부 거부.
- `public.registration_status()` RPC — 로그인 화면이 어느 직책이 미등록인지 판단하는 용도 (`{president: bool, admin: bool}`만 노출).
- `public.app_settings`의 `setup_mode` + `public.set_setup_mode(bool)` — 세팅 모드 스위치. 상세는 `docs/02_SECURITY_RULES.md` 참고.
- 무료 플랜 주의: 약 1주 이상 무활동 시 프로젝트 일시정지 가능(데이터 보존, 대시보드 원클릭 복구).

## 반입대장(`intake`) — DB 설계 상세

> 트리거·의무 체크리스트 본문은 `CLAUDE.md`의 "📥 반입대장 강제 점검"에 있다. 여기는 테이블·컬럼 설계 배경만.

- **`public.intake` 반입대장** — 들어온 모든 자료(대통령업로드/코워크수집/기관회신/포털다운로드/금고기존)를 **판독 전에 먼저 등재**한다. `상태`: 미판독 → 판독중 → 판독완료 → 금고편입/무관종결.
  - **⚠️ 같은 `evidence_no`가 여러 줄인 것 = 중복이 아니다(2026.8.4 신설, `기록유형` 컬럼).** 정보공개 한 건은 원처분 통지 → 이의신청 연장통지 → 행정심판·소송 제소기한 → 제출 확인까지 사건이 진행되며 **단계마다 기한·조치가 달라** 한 줄로 합칠 수 없다. 그래서 `evidence_no`가 같아도 여러 줄이 쌓이는 것이 정상 설계다. 이 구분을 표시하는 것이 `기록유형`(원처분/원처분_예비/연장통지/소송기한/제출확인/재검증/대장정리/혼입별건/미분류) 컬럼이다.
    - **진짜 중복 판정은 `evidence_no`가 아니라 `evidence_no + 기록유형` 조합으로 한다**: `select evidence_no, 기록유형, count(*) from public.intake group by evidence_no, 기록유형 having count(*)>1;` — 이 조회가 0건이면 중복이 아니라 정상적인 단계 누적이다.
    - 새 줄을 등재할 때는 **반드시 `기록유형`을 채운다.**
    - 유래: `docs/07_INCIDENT_HISTORY.md#2026-08-04-record-type`
- **`public.v_intake_todo`** — 미판독·판독중 목록.
- **`public.v_deadline`** — 기한 보유·미처리 건, 임박순(`남은일수` 포함).
- **`public.posts_read` + `public.v_posts_unread`** — **게시판 기록 판독 추적**(2026.7.30 신설). `posts`(기록 원본)는 손대지 않고 별도 표로 덮는다. `판독요지`는 NOT NULL + 빈값 거부이므로 **요지 없이 "읽었다"고 표시하는 것이 구조적으로 불가능**하다.
- **`public.v_intake_status`** — 한 줄 현황(`신규미판독`/`소급미판독`/`기록미판독`/`기한임박_2주내`/`기한경과_미처리`/`기한보유`/`대장총건수`/`게시판총건수`/`뼈대_기한도과`/`뼈대_미연결사실`/`뼈대_미해소상충`/`지도최종게시일`/`지도갱신필요`).
  - **`지도최종게시일`/`지도갱신필요`(2026.8.7 신설)** — "통합 사건 지도"(현황판·타임라인 다이어그램, `posts.tags`에 `사건축`·`통합지도` 포함)는 DB를 실시간으로 읽어 그리는 화면이 아니라 **누군가 요청한 시점에만 그려지는 정지화면**이다. `fact`·`issue`·`statute`에 아무리 쌓여도 지도는 저절로 안 바뀐다. `지도갱신필요`는 마지막 지도 게시일 이후 새로 쌓인 `fact`(생성)·`issue`(변경)·`statute`(확보) 건수의 합.
  - 유래: `docs/07_INCIDENT_HISTORY.md#2026-08-07-map-refresh`
  - **`신규미판독`과 `소급미판독`은 다른 축이다.** 신규 = 새로 들어온 것(대통령업로드·기관회신 등), 소급 = 금고에 원래 있던 미판독분. **착수 정지 조건은 `신규미판독`에만 걸린다** — 섞어 놓으면 경보가 항상 울려 경보가 아니게 된다.
  - **뼈대 3종은 2026.8.5 신설**(`public.deadline_critical`·`public.fact_conflict`·기존 `v_fact_orphan`을 이 뷰에 편입) — `v_fact_orphan`이 이미 위험신호 6건(F-047 감사원청구·F-048 권익위신고·F-051 형사시효 등)을 잡고 있었는데 아무도 조회하지 않아 방치된 사고가 있었다. 새 뷰를 따로 만들어도 강제 브리핑에 안 걸리면 똑같이 묻힌다는 교훈으로, 뼈대 위험신호를 별도 조회가 아니라 브리핑 자체에 편입했다.
